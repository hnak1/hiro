### Problem（課題）

1. **スコアリング式がroadmap完了状態を反映していない**
   - [x]（Claude作業完了・ユーザー対応待ち）と [ ]（未着手）を区別できないため、「実際には何もすることがない」issueが上位に来る
   - 今回の上位3件（#12, #15, #13）はすべてroadmap[x]済みで、確認・報告しか実施できなかった

2. **GitHub権限制限でissueのclose・commentが不可**
   - すべてのclose操作が「Resource not accessible by integration」で失敗
   - open issueが6件あるが、そのうち5件はroadmap上は完了済み

3. **最高緊急度タスク（#10）がスコア最下位（16点）**
   - 推薦書②のタイムリミット超過1日・実質最終期限なのにラベルなし・継続中という特性でスコアが低い
   - スコアリングが「緊急度」を十分に拾えていない

4. **前回orchestrate（2026-03-28）と上位2件が重複**
   - #12, #15は前回も実行済み（#12[22]・#15[19]）
   - 同じissueを繰り返し「確認」するだけになっている

### Try（次回改善）

1. **スコアリング式にroadmap状態フィルターを追加する**
   ```
   実行候補 = open GitHub Issues ∩ roadmap状態が [x] 以外
   ```
   → [x]済みはスキップ or ボーナス-10点

2. **緊急度フラグを追加する（🚨ラベル or キーワード検出）**
   - roadmap本文に「タイムリミット」「緊急」「期限超過」が含まれる場合 → スコア+5
   - #10は実質スコア21点に相当し、上位3件入りが妥当

3. **issue-chainとの連携を確認する**
   - GitHub ActionsのissueCloseトリガーが機能しない状況では、手動でroadmapを管理する必要がある
